# บริษัท เรื่องผีไว้ใจผม จำกัด

**Trust Me, It’s Ghosts Co., Ltd.** — เกม TRPG สืบสวนเรื่องผีภาษาไทยบนเว็บ สำหรับผู้สืบสวน 2–6 คนและ DM 1 คน เล่นร่วมกันผ่าน Socket.IO

DM เป็นผู้ตัดสินสถานการณ์และนำเรื่อง สคริปต์กับคำถาม–คำตอบเป็นแนวทางสำหรับเตรียมและเล่าฉาก ผู้เล่นเสนอวิธีลงมือได้อิสระ เซิร์ฟเวอร์ตรวจสิทธิ์ ประมวลผลทอยและการต่อสู้ และบันทึกสถานะร่วมกัน

## สถานะปัจจุบัน

- **CASE001 — เสียงร้องจากสวนกล้วย:** ใช้งานในเกม รุ่นเนื้อเรื่องเริ่มต้น **v5.5 Playtest** มี 31 ฉาก ช่วง A–F และ H1 พร้อมตอนจบ A–D และการ์ดทอยตามสคริปต์ 17 ใบ
- **CASE002 — งานวัดคืนที่ 8:** แสดงตัวอย่าง «บทต่อไปจะมาเร็ว ๆ นี้» บนหน้าแรก ยังเลือกเล่นเป็นคดีใหม่ไม่ได้
- **CASE003:** แสดงตัวอย่างคดีในอนาคต ยังไม่มีระบบเล่นคดีนี้
- ภาพฉาก 18 ภาพจับคู่กับฉาก v5.5 ครบ 31 ฉาก ผู้เล่นเห็นภาพตามบทเปิดที่ DM ส่งถึงตนแล้ว ดู [รายละเอียดภาพฉาก](docs/case001/SCENE_ARTWORK.md)

ข้อมูลนี้อ้างอิงโค้ดใน working tree ปัจจุบัน ไม่ใช่การยืนยันว่าบนเว็บที่ deploy อยู่ได้รับการอัปเดตครบแล้ว

## เริ่มพัฒนาในเครื่อง

ใช้ Node.js ที่รองรับ Vite 6 (20.19+ หรือ 22.12+; การตั้งค่า deploy ของโปรเจกต์ใช้ Node 24.x) และ npm รันคำสั่งจากโฟลเดอร์ที่มี `package.json` หลัก

```sh
npm ci
npm run dev
```

เปิด URL ที่ Vite แสดงใน terminal โดยปกติเป็น `http://localhost:5173` เซิร์ฟเวอร์เกมใช้พอร์ต `3001` เป็นค่าเริ่มต้น คำสั่ง dev จะ build shared ก่อน แล้วเปิด shared watcher, server และ client ร่วมกัน

ตำแหน่งโปรเจกต์บนเครื่องพัฒนาปัจจุบัน:

```text
C:\Users\Frank\Documents\Codex\2026-11-04\create-the-initial-project-for-baan\outputs\baan-sangob-co
```

ดู [โครงสร้างและตำแหน่งไฟล์](docs/PROJECT_LAYOUT.md) ก่อนแก้สำเนาในโฟลเดอร์อื่น

## วิธีเล่นและเครื่องมือ DM

1. สร้างห้อง ให้หนึ่งคนรับบท DM แล้วให้ผู้เล่นเข้าห้องและเลือกตัวละคร
2. DM เริ่มคดี เลือก ACT และฉาก จ่ายบทเปิด แล้วให้ทีมบอกว่าจะทำอะไร
3. ใช้คู่มือฉากและคำตอบ NPC ประกอบการตัดสิน ส่งบทเมื่อข้อมูลนั้นเกิดขึ้นหรือเปิดเผยจริง
4. เมื่อมีความไม่แน่นอน DM เลือกผู้ทอย Stat และ DC ส่งการ์ดให้ผู้เล่น แล้วอ่านผลและจ่ายบทตอบ
5. เมื่อเกิดการเผชิญหน้า ใช้คำสั่งในฉากต่อสู้ และบันทึกผลตามสิ่งที่เกิดขึ้นจริง

### ACT กับฉากแยกกัน

สำหรับ v5.5 DM เปลี่ยน ACT A–E หรือช่วงท้ายได้โดยฉากและตำแหน่งทีมคงเดิม การเลือกฉากย้ายทีมไปสถานที่ของฉากนั้น แต่ไม่เปลี่ยน ACT ตามไปด้วย ต้องจบการเผชิญหน้าก่อนเปลี่ยน ACT หรือฉาก การอ่านคู่มือล่วงหน้าไม่ใช่การเปิดฉากให้ผู้เล่นเห็น

### คู่มือสำหรับ DM มือใหม่

ทุกฉาก v5.5 มีสรุปสามช่อง **เห็นอะไร / ชวนถามอะไร / เลือกผลแบบไหนได้** เป็นคำแนะนำให้เลือกตามการกระทำจริง การเปิดอ่านไม่ส่งบทหรือเปลี่ยนสถานะเกม

คลังคำถามเรียงตาม **NPC ผู้พูด / DM บรรยายและอ่านเอกสาร / คำแนะนำเฉพาะ DM** มีตัวกรอง ค้นหา และไฮไลต์ข้อสำคัญ ข้อความพร้อมอ่านแยกจากคำแนะนำลับ หากไม่มีบทพร้อมอ่าน DM เขียนคำตอบก่อนส่งได้

ใช้ «เล่า / ตอบนอกสคริปต์» เพื่อส่งบทบรรยายหรือบทพูด NPC ที่เหมาะกับสถานการณ์ ข้อความนี้อยู่ในประวัติที่ส่งจริง แต่ไม่สร้างหลักฐานหรือเปลี่ยนผลคดีอัตโนมัติ ให้บันทึกเหตุการณ์ผ่านคำสั่งที่เกี่ยวข้องด้วย

### หลักการทอยและต่อสู้

- จุดทอยตามสคริปต์ใช้ Stat ของบท DM เลือก DC ที่ระบบรองรับก่อนส่งการ์ดได้ ค่าแนะนำของการ์ดเดิมยังคงอยู่
- Full คือคะแนนถึง DC, Partial คือต่ำกว่า DC 1–3 และ Failure คือต่ำกว่าอย่างน้อย 4 เซิร์ฟเวอร์บันทึกผลครั้งเดียว
- คะแนนส่งให้ทีมทันที ส่วนบทตอบรอ DM เลือกส่ง ไม่ทอยใหม่เมื่อจ่ายบท และไม่เปลี่ยนผลด้วยการเลือกข้อความ
- การทอยที่ DM สร้างเองไม่มีบทตอบสำเร็จรูปผูกไว้ ให้ DM บรรยายตามผลจริง
- v5.5 ไม่มีตัวจับเวลาเนื้อเรื่อง และ HP 0 ไม่ทำให้ตัวละครตายอัตโนมัติ การคุกคามต้องมีจังหวะให้รับมือก่อน DM บันทึกผลที่เกิดจริง
- Final v5.5 ใช้การจัดการวงป้องกันสามขั้นและการปลดกำไล การทำให้ร่างผีหมดแรงเพียงอย่างเดียวไม่ถือว่าหยุดพิธี

### ตัวละครและโหมดพื้นฐาน

`BASIC_RULES_MODE` เป็นค่าคงที่ใน `packages/shared/src/index.ts` และเปิดใช้อยู่ ไม่ใช่ environment variable

โหมดพื้นฐานคง 6 อาชีพ ค่า Stat และ Focus พร้อมคำสั่งต่อสู้พื้นฐาน รวมการพยุงเพื่อน HP 0 และแก้พันธนาการ พักการเลือกพรสวรรค์ ท่าพิเศษ และโบนัสเฉพาะอาชีพ โค้ดความสามารถและข้อมูลเก่ายังเก็บไว้เพื่อรองรับระบบเดิม แต่ไม่อนุญาตให้ใช้ความสามารถเหล่านั้นในโหมดพื้นฐาน

ระบบภูมิหลังและโบนัสภูมิหลัง +2 ยกเลิกแล้ว เซฟเก่าที่มีข้อมูลภูมิหลังยังโหลดได้โดยข้อมูลนั้นไม่มีผลทดสอบ ประวัติตัวละครยังใช้ประกอบการสวมบทได้

## เซฟและเล่นต่อข้ามวัน

ห้องเนื้อเรื่องที่เริ่มคดีแล้วบันทึกลง `packages/server/saves` โดยอัตโนมัติ ตั้ง `CASE_SAVE_DIR` เพื่อเปลี่ยนตำแหน่ง หรือกำหนดเป็นค่าว่างเพื่อปิดการบันทึกไฟล์ ห้องที่ยังไม่เริ่มคดีอยู่ในหน่วยความจำ

- DM พักคดี ดาวน์โหลดเซฟ และจัดสมาชิกที่มาเล่นในวันนั้นได้ โดยพักตัวละครของคนที่มาไม่ได้ไว้
- ผู้เล่นใช้เบราว์เซอร์เดิมกลับเข้าห้องด้วยกุญแจเล่นต่อได้ หากห้องและข้อมูลในเบราว์เซอร์ยังอยู่
- ห้องที่โหลดกลับมาจะพักไว้ให้ DM ตรวจและเปิดเล่นต่อ
- ไฟล์เซฟเสียถูกแยกเป็น `.json.invalid-<เวลา>` เพื่อกู้คืน โดยไม่ขัดขวางห้องอื่น หากสำรองอัตโนมัติล้มเหลว DM จะเห็นคำเตือน

ไฟล์เซฟมีข้อมูลลับและกุญแจเข้าห้อง เก็บบนพื้นที่ส่วนตัว ใช้โฟลเดอร์หนึ่งต่อเซิร์ฟเวอร์หนึ่งตัว บนบริการที่ไม่เก็บไฟล์ข้ามการ redeploy ให้ดาวน์โหลดเซฟไว้ หรือตั้งพื้นที่เก็บถาวร ดู [คู่มือเล่นต่อและนำเข้าเซฟ](docs/SESSION_RESUME.md)

## การตั้งค่าและ build

| ค่า | ใช้ที่ | ความหมาย |
| --- | --- | --- |
| `PORT` | Server | พอร์ต HTTP/Socket.IO ค่าเริ่มต้น `3001` |
| `CLIENT_ORIGIN` | Server | Origin ของหน้าเว็บ ใน production ต้องเป็น HTTPS และไม่มี path หรือ `/` ปิดท้าย |
| `NODE_ENV=production` | Server | เปิดการตรวจค่า production; ต้องระบุ `CLIENT_ORIGIN` |
| `VITE_SERVER_URL` | Client | Origin ของเซิร์ฟเวอร์เกม ฝังตอน build; production ต้องเป็น HTTPS |
| `CASE_STORY_VERSION` | Server | เวอร์ชันสำหรับห้องใหม่ ค่าเริ่มต้น `5.5`; รองรับ `4.1`, `4.3`, `5.1`, `5.2`, `5.3` ด้วย |
| `CASE_SAVE_DIR` | Server | โฟลเดอร์เซฟส่วนตัว; ค่าว่างปิดการบันทึกไฟล์ |
| `CASE001_LETHAL=true` | Server | ตัวเลือกกติกาเก่าสำหรับเวอร์ชันที่รองรับ ไม่ใช่ปุ่มเปิดสิทธิ์เสียชีวิตของ v5.5 |

ตัวอย่าง PowerShell สำหรับ build โดยแทน URL ด้วยเซิร์ฟเวอร์จริง:

```powershell
$env:VITE_SERVER_URL = 'https://your-game-server.example.com'
npm run typecheck
npm run build
npm start
```

`npm start` เปิดเฉพาะเซิร์ฟเวอร์ที่ build แล้ว ไม่ได้เสิร์ฟหน้า client เซิร์ฟเวอร์มี health check ที่ `/healthz` ส่วนหน้าเว็บ build อยู่ใน `packages/client/dist` การแก้ `VITE_SERVER_URL` ต้อง build client ใหม่

ดู [การตั้งค่า deploy บน Render](DEPLOYMENT.md) สำหรับคำสั่ง build และ origin โดยใช้ **v5.5 เป็นค่าเริ่มต้นตามโค้ดปัจจุบัน** ข้อความเรื่องค่าเริ่มต้น v4.3 ในเอกสาร deploy เดิมเป็นข้อมูลเก่า

## ตรวจงาน

หลังติดตั้ง dependencies และ build shared แล้ว รันจากโฟลเดอร์หลัก:

```sh
npm run typecheck
npx tsx --test packages/server/tests/*.test.ts packages/client/tests/*.test.ts
node --test packages/client/tests/*.test.mjs
```

ทดสอบเซิร์ฟเวอร์ผ่าน Socket.IO หลัง build:

```sh
node --test tests/smoke/production-smoke.test.mjs tests/smoke/production-v51-smoke.test.mjs tests/smoke/production-session-smoke.test.mjs tests/smoke/production-npc-placement.test.mjs tests/smoke/autosave-status.test.mjs
```

ยังไม่มีคำสั่ง `npm test` ที่รวมทุกชุดไว้ในระดับ root การตรวจภาพจริงบน desktop/mobile และการเล่นผ่านเครือข่ายจริงยังจำเป็นแยกจาก unit และ smoke tests

## โครงสร้างโปรเจกต์

| ตำแหน่ง | หน้าที่ |
| --- | --- |
| `packages/client` | React, TypeScript, Vite, ภาพฉาก 2D และ Socket.IO client |
| `packages/server` | Node.js, Socket.IO, สถานะเกม กติกาฝั่ง server และระบบเซฟ |
| `packages/shared` | Types และกติกาที่ใช้ร่วมกัน โดยไม่ผูกกับ UI หรือเครือข่าย |
| `packages/server/scenarios/case-001` | เนื้อเรื่อง Q&A การ์ดทอย สเตตัส และข้อมูล runtime แยกเวอร์ชัน |
| `packages/client/src/assets/case-001` | ภาพฉากและตัวละครที่เกมโหลดจริง |
| `docs/case001` | แนวทางปัจจุบัน รายงานตรวจ และประวัติ CASE001 |
| `docs/reference` | ต้นฉบับเนื้อเรื่องและเอกสารอ้างอิง บางชุดเก็บเฉพาะเครื่อง |
| `assets/source` | ภาพต้นฉบับ |

# บริษัท เรื่องผีไว้ใจผม จำกัด

**Trust Me, It’s Ghosts Co., Ltd.**

A Thai cooperative ghost-hunting browser game for 2–6 online investigators, with one human GM. The GM leads the team between illustrated scenes and answers player questions. The team resolves scripted D20 checks, and uses a grid during encounters.

ระบบภูมิหลังและโบนัสภูมิหลัง +2 ถูกยกเลิกแล้ว ตัวละครใหม่เลือกอาชีพ พรสวรรค์ และชื่อผู้เล่น ประวัติที่เตรียมให้ยังใช้สวมบทได้ เซฟเก่าที่มีข้อมูลภูมิหลังยังโหลดได้ แต่ข้อมูลนั้นไม่มีผลทดสอบ การจำกัดการใช้ความสามารถอื่นยังคงเดิม

ช่วงทดสอบปัจจุบันเปิดโหมดพื้นฐาน (`BASIC_RULES_MODE`): พักการเลือกพรสวรรค์และคำสั่งท่าพิเศษ รวมโบนัสเฉพาะอาชีพ โดยคง 6 อาชีพ ค่า Stat เดิม Focus และคำสั่งต่อสู้พื้นฐาน ผู้เล่นยังช่วยเพื่อน HP 0 ที่อยู่ติดกันและแก้พันธนาการได้ ข้อมูลพรสวรรค์เก่าและโค้ดความสามารถยังเก็บไว้ แต่เซิร์ฟเวอร์ไม่อนุญาตให้เรียกใช้ในโหมดนี้ เทสต์ระบบความสามารถเดิมยังทดสอบแยกด้วย WorldStore โหมดเดิม

หลังทอยจุดตรวจตามสคริปต์ เซิร์ฟเวอร์คำนวณและบันทึกผลหนึ่งครั้ง Full คือคะแนนถึง DC, Partial คือต่ำกว่า 1–3, Fail คือต่ำกว่าอย่างน้อย 4 ผลคะแนนส่งให้ทั้งทีมทันที แต่บทตอบรอ DM เลือกส่งจากหน้า “อ่าน / จ่ายบท” หรือ “D20” โดยส่งบทบรรยาย บทพูด NPC หรือส่วนที่เหลือทั้งหมดได้ ระบบใช้บทตามผลจริง ไม่ให้ DM เปลี่ยนผลด้วยการเลือกบท และไม่เรียกทอยใหม่เมื่อส่งคำตอบ คิวกับสถานะส่วนที่ส่งแล้วอยู่ในเซฟเดิมด้วย การทอยที่ DM สร้างเองไม่มีบทตอบสำเร็จรูปผูกไว้ ให้ DM ใช้คู่มือฉากประกอบ

เมื่อผู้เล่นส่งคำขอทอย DM เลือก DC 11, 14, 17, 20 หรือ 22 ก่อนส่งการ์ดได้ จุดทอยตามสคริปต์แสดง DC ที่ผู้เขียนแนะนำและล็อก Stat ตามบท หาก DM เปลี่ยน DC ผลและบทตอบใช้ DC ที่เลือก การ์ดที่ส่งแล้วเก็บค่านั้นไว้จนทอย แม้กลับเข้าห้องใหม่

หน้าผู้เล่นแบ่งเป็นแท็บฉาก บทเล่า ลงมือทำ ตัวละคร และสมุดคดี โดยมีสถานะย่อแสดงตลอด การ์ดทอยที่รออยู่ยังแสดงเหนือแท็บย่อย ไม่มีคำสั่งรับเงินล่วงหน้าในโหมดพื้นฐาน ยอดที่เคยรับในเซฟเก่ายังคงบันทึกตามจริง ฝั่ง DM มาร์คบทที่ส่งแล้วอัตโนมัติและเก็บสถานะในเซฟ แสดงทั้งข้างบท NPC และรายการบทที่ส่งแล้วในสถานที่นั้น

## Development

Requires Node.js 20.19+ or 22.12+ and npm.

```sh
npm install
npm run dev
```

Open the Vite URL printed in the terminal (normally http://localhost:5173). The Socket.IO server listens on port 3001 by default. Set `PORT` for the server and `VITE_SERVER_URL` for the client if needed; restart the relevant process after changing them.

Set `VITE_SERVER_URL` to the public HTTPS server origin before running `npm run build`. Run `npm run typecheck` to check types and `npm start` to start the built server. For Render settings and production smoke tests, see [DEPLOYMENT.md](DEPLOYMENT.md).

## Structure

- `packages/client`: React shell, Phaser rendering, and Socket.IO client adapter.
- `packages/server`: Node.js Socket.IO connection boundary.
- `packages/shared`: framework-independent types, rules boundary, and scenario data.

Game rules and scenario data are independent of Phaser and networking. The shared package is built first and watched during development. Assets are deliberately minimal and generated by the placeholder renderer.

### CASE 001 v5.1

ห้องเนื้อเรื่องใหม่ใช้ v5.1 พร้อมข้อมูลฉาก A1–F6/H1, State Contract และ Ending Resolver ใหม่ รายงานก่อนแก้และสารบัญอยู่ใน [CASE001_V51_PLAN.md](docs/CASE001_V51_PLAN.md) และ [CASE001_V51_STORY_MAP.md](docs/CASE001_V51_STORY_MAP.md) อ่านข้อค้างและผลทดสอบใน [CASE001_V51_QA.md](docs/CASE001_V51_QA.md)

จุดทอย 16 รายการคง Stat/DC/ช่วงผลต้นฉบับ และล็อก DC ฝั่งเซิร์ฟเวอร์สำหรับ v5.1 บทตอบตามคำถามต้องให้ DM ยืนยันเงื่อนไขที่เกิดจริงก่อนส่ง แยกการเก็บเอกสาร การยืนยันหลักฐานเพียงพอ และการเปิดเผยจริงออกจากกัน โดยไม่กำหนดกฎหมายหรือเกณฑ์พยานใหม่

Lethal Variant ปิดเป็นค่าเริ่มต้น เปิดด้วย `CASE001_LETHAL=true` ก่อนเริ่มเซิร์ฟเวอร์ หรือประกาศผ่านหน้า DM ในบท A เวลา 03:00 ตรวจครั้งเดียวและไม่จบเกม การคุกคามใน E5/F5 ต้องมีจังหวะรับมือและผลตามกติกาจริงก่อน DM บันทึก ไม่มีการเปลี่ยน HP0 เป็นตายอัตโนมัติ

เซฟเก่าใช้เวอร์ชันเดิมต่อ ตั้ง `CASE_STORY_VERSION=4.3` หรือ `CASE_STORY_VERSION=4.1` เพื่อเลือกเวอร์ชันเดิมสำหรับห้องใหม่ ไม่มีการเขียนทับเซฟเดิม

### CASE 001 v4.3 Guided Linear (เวอร์ชันเดิม)

ห้องที่เลือก v4.3 เดินบท A → B → C → D → E → Final → Ending ผู้ดำเนินเรื่องเลือกฉากย่อยและส่ง cue ก่อนเสนอหัวข้อถาม ผู้เล่นถามอิสระได้ โดย DM เลือกคำตอบตามความรู้ของ NPC ก่อนออกบท DM เตรียมสมุดคดีให้ผู้สืบสวนยืนยันแทนทีม เมื่อยืนยันแล้วไม่ย้อนบทเก่า แต่ยังสำรวจฉากย่อยในบทเดียวกันได้

คงจุดทอยเสริม 16 รายการ คำใบ้สามระดับ หลักฐานสำรองในบทถัดไป และทางจบโดยไม่ต่อสู้ ดูการเชื่อมข้อมูล ข้อแตกต่าง และวิธีทดสอบใน [CASE001_V43_INTEGRATION.md](docs/CASE001_V43_INTEGRATION.md)

ห้องที่บันทึกก่อนอัปเดตใช้เวอร์ชันเดิมต่อ ไม่มีการแปลงไฟล์เซฟอัตโนมัติ ตั้ง `CASE_STORY_VERSION=4.1` ฝั่งเซิร์ฟเวอร์เพื่อให้ห้องใหม่ใช้ระบบก่อนหน้าได้

### CASE 001 ฉบับเดิม v4.0

ห้องโหมดเล่าเรื่องใช้บทและเงื่อนไขจาก Story Script v4.0 และอ้างอิงรหัสฉากกับหลักฐานจาก Story Flow v4.0 ข้อมูลเกมอยู่ใน [case-001.v4.json](packages/server/scenarios/case-001/case-001.v4.json) ผู้ดำเนินเรื่องเริ่มคดี พาทีมเปลี่ยนฉาก และจ่ายบทเล่ากับคำตอบผ่านคิว ผู้เล่นส่งคำถามหรือเสนอจุดหมายเป็นข้อความได้

Final ใช้ฉากเรือนไม้ร้างเดิม หลังหยุดพิธีจะกลับสู่บทสนทนาและทางเลือกจัดการแม่แก้ว หากทีมชนะการต่อสู้ในสวน จะเหลือจุดพันธนาการให้คลายน้อยลงใน Final โดยใช้ค่าพลังชีวิตจากระบบต่อสู้เดิม เมื่อตีสามขณะพิธียังทำงาน เกมใช้โทษความหลอนสูงสุดที่มีอยู่และให้ทีมเล่นต่อ

ข้อมูลชุดนี้ยังเป็นฉบับ Playtest ใช้ Story Script ต้นฉบับสำหรับบทด้นสดและจังหวะย่อยที่ยังไม่มีคำสั่งในเกม ระยะเวลารวมร่างและตัวเลข Combat Lite ต้องยืนยันแยกก่อนปรับกติกา

### CASE 001 v4.1 และการบันทึกห้อง

ห้อง v4.1 เดิมและห้องใหม่ที่ตั้ง fallback ใช้บท v4.1 และจุดทอยเสริม 16 รายการ คำขอแสดง Core Stat และ DC ก่อนส่งการ์ด ผลทอยและข้อความตามผลถูกส่งจากเซิร์ฟเวอร์ถึงทั้งทีม ส่วนบทเต็มและเงื่อนไขอยู่ในหน้า DM

ตั้ง `CASE_SAVE_DIR` เป็นโฟลเดอร์ส่วนตัวที่เซิร์ฟเวอร์เขียนได้ เพื่อบันทึกห้องเนื้อเรื่องหลังเริ่มคดีและโหลดอัตโนมัติเมื่อเปิดเซิร์ฟเวอร์ใหม่ ผู้เล่นรีเฟรชเพื่อกลับห้องเดิม หรือเปิดเบราว์เซอร์เดิมแล้วเลือก “เล่นคดีที่บันทึกไว้ต่อ” ไฟล์บันทึกมีข้อมูลลับของคดีและกุญแจกลับเข้าห้อง จึงต้องอยู่บนพื้นที่เก็บข้อมูลส่วนตัวและคงอยู่ข้ามการรีสตาร์ต ใช้โฟลเดอร์หนึ่งต่อเซิร์ฟเวอร์หนึ่งตัว หากไม่ตั้งค่า จะบันทึกที่ `packages/server/saves` โดยอัตโนมัติ ตั้งเป็นค่าว่างเพื่อปิดการบันทึกไฟล์

### เล่นต่อข้าม session และจัดทีมวันนี้

DM พักคดีแล้วดาวน์โหลดไฟล์เซฟเก็บไว้ วันถัดไปนำเข้าหากห้องบน Render Free หาย และเลือกพักตัวละครคนที่มาไม่ได้ก่อนเปิดเล่นต่อ ข้อมูลผู้เล่นเดิมครบ 6 คนยังอยู่ ดู [คู่มือเล่นต่อ](docs/SESSION_RESUME.md)

# เล่นคดีต่อในวันถัดไปและจัดทีมประจำ session

รองรับ DM หนึ่งคนและตัวละครผู้เล่นเดิม 2–6 คน ใช้ไฟล์เซฟของ DM ข้ามการพักเครื่องของ Render Free โดยไม่เพิ่มฐานข้อมูลหรือบริการเสียเงิน

## จบการเล่นแต่ละวัน

1. DM กด **พักคดี** ก่อนทุกคนออก
2. ถ้ามีแผนหรือคำขอทอยที่ยังไม่ทำ ให้เลือกเก็บไว้ หรือยกเลิกเฉพาะรายการที่ยังไม่ทอยด้วยปุ่มที่ยืนยันชัดเจน ผลทอยที่เกิดแล้วไม่ถูกลบ
3. กด **ดาวน์โหลดเซฟสำหรับเล่นครั้งหน้า** และตรวจว่าไฟล์ JSON ถูกดาวน์โหลดสำเร็จ เก็บไฟล์นี้ไว้กับ DM
4. ใต้ปุ่มมีรหัสกลับเข้ารายคน ส่งให้แต่ละคนเฉพาะรหัสของตน รวมถึง DM ควรเก็บรหัสของตนไว้ด้วย
5. กด **ออกชั่วคราว** หรือปิดหน้าเกม ตัวละครและสมาชิกยังอยู่ การออกชั่วคราวของ DM ทำให้คดีพักรอจัดทีม

ไฟล์มีความลับ DM และสิทธิ์ของสมาชิกทั้งห้อง ไม่ควรส่งไฟล์รวมให้ผู้เล่น

## เริ่มครั้งถัดไป

1. ถ้าห้องเดิมยังอยู่ ใช้ **เล่นคดีที่บันทึกไว้ต่อ** หรือกรอกรหัสส่วนตัว ไม่ต้องนำเข้าทับห้องที่ยังอยู่
2. ถ้าเซิร์ฟเวอร์เสียข้อมูลหลังพักเครื่องหรือ deploy ให้ DM เลือก **นำเข้าเซฟครั้งก่อน** จากหน้าเข้าห้อง ไฟล์จะคืนห้องเดิมและให้ผู้ถือไฟล์เข้าบท DM เดิม
3. ผู้เล่นที่มาวันนี้กลับเข้าด้วยเบราว์เซอร์เดิมหรือรหัสส่วนตัว ไม่ใช้รหัสห้องเพื่อสร้างตัวละครซ้ำ
4. ห้องที่นำเข้าหรือโหลดจาก disk จะอยู่ในสถานะพักเสมอ เวลาเกมไม่เดินเอง
5. DM เลือกผู้เล่นใน **session วันนี้** เอาเครื่องหมายของคนที่มาไม่ได้ออก ตัวละครเหล่านั้นยังมีอาชีพ HP, Sanity, Focus, AP และสิทธิ์กลับเข้าครบ แต่ไม่ปรากฏในสนามและไม่เข้าคิว
6. หากมีแผน/คำขอทอยค้าง ต้องจัดการก่อนเปลี่ยนทีม ใช้ปุ่มยกเลิกเฉพาะรายการที่ยังไม่ทอยได้โดยไม่สร้างผลลัพธ์ใหม่
7. กด **เปิดเล่นต่อ** เมื่อผู้เล่นที่เลือกกลับเข้าห้องครบ ต้องมีผู้สืบสวนอย่างน้อยสองคนตามเกมเดิม
8. วันที่คนที่พักกลับมา DM ติ๊กกลับขณะพักคดี ตัวละครจะเข้าฉากปัจจุบันโดยจัดช่องว่างให้ ไม่คืน HP/Focus หรือแจกไอเท็มใหม่

## ระหว่างการเผชิญหน้า

เปลี่ยนทีมขณะพักได้เมื่อยังมีตัวละครที่ลงมือได้ในฉากต่อสู้นั้นอย่างน้อยหนึ่งคน ไม่เปลี่ยน HP ศัตรูของ encounter ที่เกิดแล้ว ไม่รีเซ็ต AP หรือรอบ หากเจ้าของคิวพัก ให้ระบบเดินลำดับเดิมเมื่อ DM เปิดเล่นต่อ รวมจังหวะฝ่ายศัตรูตามกติกา ไม่ข้ามให้ฟรีระหว่างเตรียมทีม

## การเก็บข้อมูลและความเข้ากันได้

- ใช้ endpoint session:export, session:import และ room:resume เดิม รหัสห้อง สมาชิก และ token เดิมอยู่ในไฟล์เดียวกัน
- นำเข้าได้จากหน้าเข้าห้องเท่านั้น ไม่เขียนทับห้องที่ยังเปิดอยู่ ตรวจข้อมูลทั้งห้องและโลกเกมใน store ชั่วคราวก่อนเผยแพร่จริง
- รูปแบบไฟล์: format=baan-session, version=1 ขนาดไม่เกิน 8 MB ตรวจเป็น UTF-8 bytes; Socket.IO เผื่อขนาด envelope ไว้
- เซฟ disk เดิมยังอ่านได้ ไม่มีการลบหรือแปลงทับข้อมูล เพียงโหลดแล้วพักก่อนเล่นต่อ
- สมาชิกที่พักยังอยู่ใน membership และ characters; ตำแหน่งจริงยังอยู่ใน checkpoint ระบบกรองออกเฉพาะการลงมือและสนามที่ใช้งาน
- เซฟใช้ dedupe history, ผลทอย, คิว DM และ State เดิม ไม่มีการ reroll หรือ Toll 03:00 ซ้ำ
- Client รุ่นเก่าไม่สามารถนำเข้าไฟล์รูปแบบใหม่นี้ ต้องใช้เว็บรุ่นที่มีเครื่องมือนำเข้า/จัดทีม
- ทางย้อนเวอร์ชันคือเก็บไฟล์ต้นฉบับและใช้ build ที่รองรับรูปแบบนี้ในการคืนข้อมูล ห้ามนำไฟล์ JSON ไปวางแทน internal save ของ build เก่าโดยตรง

## ข้อจำกัด

ไฟล์ที่ดาวน์โหลดล่าสุดคือจุดกู้คืน หาก Render ลบไฟล์ในเครื่องก่อน DM ดาวน์โหลด ความคืบหน้าหลังไฟล์ล่าสุดจะไม่อยู่ในสำเนานั้น วิธีนี้ไม่ใช่ cloud autosave ข้ามการพักเครื่อง

ไม่เพิ่มบัญชีผู้ใช้ ฐานข้อมูล paid API หรือการเปลี่ยน DM อัตโนมัติ ผู้มีไฟล์รวมมีสิทธิ์คืนบท DM จึงต้องเก็บไฟล์เป็นส่วนตัว

## การตรวจสอบ

- Unit/integration ชุดรวม server/client: 199 ผ่าน รวม 6 กรณีเฉพาะการคืน session
- Socket.IO production smoke: 4 ผ่าน รวมการนำเข้าไฟล์แบบ multibyte, คืนสมาชิกทั้งหกและ DM, เลือกสี่คนลงเล่น, และปฏิเสธการเปิดก่อนสมาชิกที่เลือกกลับครบ
- Build และ TypeScript ผ่าน โดยใช้ VITE_SERVER_URL=https://game.example สำหรับตรวจ build ไม่ใช่การตั้งค่า deployment จริง
- ยังไม่ได้ deploy หรือรัน human playtest เต็ม session บนบริการ Render จริง

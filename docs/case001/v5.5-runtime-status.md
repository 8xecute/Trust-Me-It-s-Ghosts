## ขอบเขตที่ยืนยันแล้ว

ผู้สร้างยืนยันให้ใช้การกระทำ `caseObjective` เดิมกับทั้งสามขั้น: 2 AP และ INT DC12 ตาม Core/Combat เดิม ไม่เพิ่ม Dice Card สำหรับปริศนา และใช้ `liteGhostHP(baseHPFor2, partySize)` เดิมสำหรับผู้เล่น 2–6 คน

## ส่วนที่ยังไม่เสร็จและข้อกำหนดที่ขัดกัน

1. **4A หลังทีมแพ้:** ศัตรูวิชัยเดิมมี HUMAN_STRIKE ระยะประชิด ความเสียหาย 1 แต่ไม่มีท่าโจมตี/การประหารผ่านพิธีที่ระบุระยะ เป้าหมาย และวิธี Resolve ไม่สร้างท่า ความเสียหาย หรือการตายเพิ่มเอง เหตุฆ่าพยานตาม 4A จึงยังไม่เปิดใช้งาน ต้องระบุว่าจะอ้างท่า/กติกาเดิมใด หรือแก้ Contract ให้ชัด
2. **Q&A และ State ใหม่:** นำเข้าครบ 262 รายการ แต่ไม่ได้เปิดทุกคำตอบ เงื่อนไขที่ยังไม่มี mapping ให้ DM ตอบเอง E3/E5/H1 ปิดคำตอบแนะนำจากฐานเดิมไว้เพื่อกันบทที่ขัดกับ Presentation Overrides ต้องทำการตรวจเงื่อนไขรายรายการต่อ
3. **คำกำกับปนใน Q&A:** คำตอบ ACT F หลายรายการมีข้อความเช่น “F5 ต้องเข้าหลังขั้น 3...” และชื่อ State ต่อท้ายบทพูด ต้องแยกข้อความส่งผู้เล่นออกจากคำแนะนำ DM ก่อนรับรองฐาน Q&A นี้ทั้งชุด
4. **F4 Contract:** Guard `F4_OCCURRED` อนุญาตเหตุผล investigate_memory/ritual_memory_reaction แต่ข้อกำหนดกลไกใหม่ระบุ ritual_shield_phase_shift ตัว Runtime ใช้ผลขั้น 2 เปิด Phase 2 ตามข้อกำหนดใหม่ ยังต้องปรับความสอดคล้องของ Contract/Q&A โดยรักษาไฟล์ต้นฉบับไว้
5. **บทเปิด F1/F2:** F1 เขียนเหมือนแม่แก้วเคยสลายทุกเส้นทาง แต่ D4 อาจไม่ได้ต่อสู้ ส่วน F2 บางผลมีเพียงคำสั่ง DM ไม่มีประโยคให้อ่าน ไม่แต่งบทเพิ่มแทน ให้ DM อ่านต้นฉบับและตัดสินใจปรับเฉพาะจุด
6. **Action-driven UX:** ยังไม่ได้แทนรายการขอทอย/บันทึกผลทั้งหมดด้วยขั้นประกาศการกระทำและเลือกเงื่อนไขแบบใหม่ ใช้ระบบตรวจสอบเดิมในส่วนที่รองรับได้ก่อน
7. **Playtest:** ยังต้องทดสอบหน้าเว็บ DM/ผู้เล่นพร้อมกัน การเล่นครบทุกฉากของ v5.5 และเส้นทาง Ending A–D ด้วยข้อมูลล่าสุด ก่อนเปิดเป็นค่าเริ่มต้น

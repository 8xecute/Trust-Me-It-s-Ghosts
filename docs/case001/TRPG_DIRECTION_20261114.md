# แนวทาง TRPG และการแก้ระบบ CASE001 — 14 พฤศจิกายน 2026

อ้างอิงผลตรวจใน `GAME_SYSTEM_AUDIT_20261114.md` และคำตัดสินล่าสุดของผู้สร้างในแชทนี้

## รูปแบบการเล่น

DM ใช้สคริปต์และคลังคำถามเป็นแนวทางสำหรับเตรียมฉากและตอบคำถาม ไม่จำเป็นต้องอ่านทุกบรรทัดหรือเดินตามลำดับบท เมื่อผู้เล่นทำสิ่งที่อยู่นอกบท DM เลือกผู้เล่าเป็น DM หรือ NPC แล้วส่งข้อความผ่าน «เล่า / ตอบนอกสคริปต์» ได้ ข้อความเหล่านี้ปรากฏให้ทีมเห็นและอยู่ในประวัติคำตอบ แต่ไม่สร้างหลักฐานหรือเปลี่ยนสถานะคดีอัตโนมัติ

ระบบยังตรวจสิทธิ์ผู้สั่งงาน ป้องกันคำสั่งซ้ำ และบันทึกผลเกมผ่านคำสั่งที่มีอยู่ การเปลี่ยนฉากระหว่างการเผชิญหน้ายังต้องจบเหตุการณ์ก่อน งานครั้งนี้ไม่ได้เพิ่มตัวแก้สถานะทุกช่องหรือเปลี่ยนกติกา DC และความสามารถตัวละคร

## จุดที่แก้ตามคำตัดสิน

1. **ต้นใน B3:** DM อนุญาตหรือให้ต้นยังไม่เปิดข้อมูลลึกได้ ตามวิธีที่ผู้เล่นเข้าหา ไม่ต้องทอย SOC ก่อนทุกครั้ง การ์ด SOC14 เดิมเป็นตัวเลือกเมื่อ DM เห็นว่ามีความไม่แน่นอนจริง การให้เปิดข้อมูลไม่สร้างผลทอยหรือหลักฐาน E08 เอง
2. **แม่แก้วใน F5:** หลังพิธีหยุดและแม่แก้วยังเป็นภัย เธอพยายามฆ่าวิชัยเมื่อทีมไม่เคยพูดคุยหรือเจรจากับเธอมาก่อน **หรือ** DM ประเมินว่าหลักฐานเอาผิดวิชัยยังไม่พอ การมีหลักฐานเพียงพอเป็นคำตัดสินของ DM และไม่บังคับรหัสหลักฐานตายตัว ไม่ต้องอ่านคำถามในสคริปต์ก่อนเริ่มเหตุ วิชัยต้องอยู่ในระยะจริง การเริ่มเหตุยังไม่ทำให้ตาย ต้องส่งเหตุให้ผู้เล่นเห็น เปิดโอกาสให้ช่วยหรือขัดขวาง แล้ว DM บันทึกผลที่เกิดจริง
3. **เกราะคุ้มกัน:** ลดความเสียหายก่อนหัก HP/Sanity และก่อนจำกัดค่าต่ำสุดที่ศูนย์ ป้องกันกรณี HP 1 รับความเสียหาย 2 ลดได้ 1 แต่กลับรอดเพราะบวกคืนหลังหัก
4. **ผู้สูญหายในเรือน:** เปิดห้องและสำรวจจริงแล้วพบดล นิด และเพิ่ม แนวทางหลักคือช่วยและพาทั้งสามขึ้นมาพักบนเรือนด้วยกัน DM บันทึกการย้ายเมื่อผู้เล่นทำจริง การขึ้นเรือนไม่เพิ่มจำนวนผู้ปลอดภัยและไม่ปลดด้ายพิธี คำถามของคนที่ยังอยู่ยังใช้ได้เมื่อแยกพาอีกคนออกไปแล้ว
5. **คำตอบผู้เล่นและข้อมูลลับ:** ข้อมูล Q&A v5.5 แยก `playerAnswer` ที่พร้อมอ่าน/ส่งออกจาก `answer` ซึ่งเก็บแนวทางสำหรับ DM ช่องส่งไม่ดึงคำสั่ง DM หรือรหัสฉากจากแนวทางมาเติมเอง ถ้ายังไม่มีบทพร้อมอ่าน จะแจ้งให้ DM เขียนก่อนส่ง คำแนะนำลับยังเปิดอ่านได้ในส่วนเฉพาะ DM
7. **เซฟ:** โหลดและตรวจแต่ละห้องแยกกันก่อนเพิ่มเข้าสู่ระบบจริง ไฟล์เสียถูกเก็บชื่อ `.json.invalid-<เวลา>` เพื่อกู้คืนและไม่ขัดขวางห้องอื่น เมื่อสำรองอัตโนมัติไม่สำเร็จ DM เห็นคำเตือนให้ดาวน์โหลดเซฟ คำเตือนจะหายเมื่อสำรองสำเร็จอีกครั้ง

## ข้อ 6 และสรุปสำหรับ DM มือใหม่ — อัปเดตตามคำอนุมัติ

เมนูส่งหลักฐาน v5.5 อ่านสถานะเก็บเอกสารที่ดินใน E4 โดยตรง ใช้ตัวเลือกแยกจาก E08 ซึ่งเป็นคำให้การต้น ตรวจซ้ำว่ายังมีเอกสารจริงก่อนบันทึกการเปิดเผย และไม่สร้างคำให้การต้นเพิ่มขึ้นเอง คงพฤติกรรมเวอร์ชันเก่าและการอ่านเซฟเดิมไว้

คู่มือ v5.5 ครบ 31 ฉากเพิ่มสามช่อง «เห็นอะไร / ชวนถามอะไร / เลือกผลแบบไหนได้» ดึงจากข้อมูลสำหรับ DM แยกไฟล์ `case-001.v5.5.beginner.json` แต่ละฉากมีคำถามชวนผู้เล่นลงมือ ไม่ใช่คำถามบังคับให้ถาม NPC การอ่านส่วนนี้ไม่ส่งข้อความหรือเปลี่ยนสถานะเกม หน้าจอแสดงเรียงสามคอลัมน์เมื่อมีพื้นที่และลดคอลัมน์ตามความกว้าง

ผลตรวจรอบอัปเดต: typecheck, production build และชุด server/client 356 รายการผ่าน รวมการเลือก/ส่งเอกสารโดยไม่มี E08 การปฏิเสธเอกสารที่ยังไม่เก็บ การตรวจซ้ำก่อนส่ง และการแสดงสามช่องในคู่มือ

## ขอบเขตข้อมูลและการตรวจ

- ใช้ runtime ที่ติดตามใน Git เป็นฐาน ไม่ได้นำชุดแก้ disclosure 35 รายการจากต้นฉบับ local มาทับทั้งชุด
- คง Dice Cards เดิม 17 ใบและตัวเลข DC เดิม การเพิ่มแนวทางผู้สร้างไม่แก้ข้อความการ์ดเหล่านั้น
- การทดสอบครอบคลุมสิทธิ์ต้น เงื่อนไขแม่แก้วทั้งสี่กรณี การช่วยแทนการตาย การขึ้นเรือน การคุ้มกันใกล้ศูนย์ ข้อความนอกบท สิทธิ์ DM การกู้ไฟล์เสีย และสถานะสำรองผ่าน Socket.IO
- ผลตรวจ: typecheck และ production build ผ่าน ชุด server/client 354 รายการผ่าน และ Socket.IO smoke 7 รายการผ่าน ตรวจแล้วว่าข้อความการ์ดเดิมครบ 17 ใบและ SHA-256 ของสคริปต์ตรง manifest การตรวจ UI รอบนี้ใช้การเรนเดอร์ทดสอบ ไม่ได้ตรวจด้วยเบราว์เซอร์จริง

## แนวคิดสำหรับ DM มือใหม่ในงานถัดไป

แต่ละฉากอาจมีสรุปสั้นสามช่อง: «สิ่งที่ผู้เล่นเห็น», «คำถามชวนเล่น» และ «ผลที่ DM เลือกได้» พร้อมตัวอย่างยอมให้สำเร็จโดยไม่ทอยเมื่อวิธีสมเหตุสมผล หากยังระบุผลไม่ได้ ให้ถามว่าตัวละครทำอย่างไรและต้องการรู้อะไร แทนการปฏิเสธเพียงเพราะไม่มีข้อความในสคริปต์

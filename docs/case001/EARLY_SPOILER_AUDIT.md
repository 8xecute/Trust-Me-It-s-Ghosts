## แยกจากกรณีที่ยังไม่ควรนับเป็นสปอยผิด

- C5_Q001/Q006/Q008 ใช้ชื่อแก้วและเรื่องช่วยคน เพราะเป็นฉากเล่าอดีตของยายโดยตรง แต่เมื่อข้ามฉากหรือยังไม่ได้แนะนำตัว ต้องมีประโยคแนะนำก่อนเรียกชื่อในบทพูด ไม่ถือว่าเข้าฉากแล้วผู้เล่นรู้ทุกเรื่องทันที
- E2_Q001 ระบุผู้จับจากคำให้การดลหลังเข้าถึงห้องและพูดได้ เป็นจุดเฉลยตามเนื้อเรื่อง ไม่ควรตัดชื่อออกเพียงเพราะพบชื่อวิชัย
- E5, H1 และ F4/F5 มีข้อมูลเฉลยสำหรับช่วงนั้น การตรวจชื่ออย่างเดียวไม่เพียงพอ ต้องดูการมาถึง หลักฐาน สภาพ NPC และผลเหตุการณ์ คำตอบหลายรายการมี guard แล้ว ไม่เสนอปลด guard
- สารบัญที่ DM อ่านล่วงหน้าและข้อมูลลับที่ขยายดูได้ ไม่ใช่ network leak โดยตัวมันเอง ปัญหาคือข้อความที่ถูกจัดเป็นคำถามชวนเล่น/บทพร้อมอ่านและข้อความพร้อมส่ง ทั้งที่เนื้อหามีเงื่อนไข

## สาเหตุร่วม

1. DM Reader แสดงชื่อคำถามทั้งหมดของฉาก แม้ปุ่มส่งถูกปิดตาม State แล้ว จึงยังสปอยผ่านชื่อหัวข้อได้
2. บทพูดที่มีเงื่อนไขถูก label เป็นบทหลัก แต่เงื่อนไขอยู่ใน context ซึ่งหน้าอ่านไม่ได้แสดงพร้อมบทเสมอ
3. บาง playerAnswer ปนข้อสรุปเจตนาและคำแนะนำ DM
4. cue ที่แปลงจากเอกสารรวมหลายย่อหน้าเข้าด้วยกัน ทำให้เหตุที่ต้องรอการตรวจถูกเล่าในบทเปิด

รายงานนี้ยังไม่แก้ต้นฉบับเนื้อเรื่องหรือ Q&A และไม่เปลี่ยน State/DC/Combat ข้อเสนอเป็นการจำกัดข้อมูลตามหลักฐานเดิม ไม่สร้างปมใหม่ งาน UI ทางสำรองในรอบเดียวกันเปลี่ยนเป็นส่วนช่วยเฉพาะฉากในหน้าดำเนินเกม และยังแยกจากการแก้เนื้อเรื่องเหล่านี้

# CASE002 — รายการตัดสินใจที่ยังเปิดอยู่

สถานะ: `design_draft / partially_approved` · วันที่ 15 พฤศจิกายน 2026

เอกสารนี้แยกสิ่งที่ผู้ใช้กำหนดแล้วออกจากกติกาและผลลัพธ์ที่ยังต้องเลือก คำว่า “แนะนำ” ไม่ใช่การอนุมัติ และตัวเลขที่ระบุเป็นข้อเสนอไม่ใช่ค่าที่เปิดใช้ใน Runtime

## มติผู้ใช้ล่าสุด

- **D01-B อนุมัติ:** ใช้ระบบ v5.5 ปัจจุบันสำหรับ CASE002: HP15, Preset/ท่าปัจจุบัน และหนึ่ง Action จบตา ไม่เปลี่ยน CASE001
- **D02-C อนุมัติแบบกติกา:** ทอย D20+BODY/RES แทนฐาน 10 ใช้ 0 AP/Focus1/1 Reaction เลือกก่อนรู้ผลโจมตี แล้วทอยหลังเฉลยตัวตน ตามรายละเอียดด้านล่าง ยังไม่มี Runtime ของ CASE002 เปิดใช้
- **D05 ผู้ใช้เลือกทางที่ 2 แล้ว:** ให้ออกแบบทางหยุดภัยถาวรหลังสังเวย ปูหลักฐานตั้งแต่ B–E รายละเอียดฉบับออกแบบใช้ไม้ครูของโรงเป็นจุดยึด ดู [FINAL Anchor Design](CASE002_FINAL_Anchor_Design.md); ตัวเลข Action/DC ยังไม่เปิด runtime
- D03, D04, D06 และ D07 ยังเปิดอยู่; การอนุมัติฐานและทอยป้องกันไม่อนุมัติค่ามนุษย์ ศัตรู การตาย วิธี FINAL หรือ DC โดยปริยาย

## ขอบเขตที่กำหนดแล้ว

ใช้พล็อต “งานวัดคืนที่แปด” ตาม Master Prompt v1.0: ประยูร อิง ครูสิงห์/นายโรง ผีผู้แสดงหน้ากาก และโครง A–FINAL มีอยู่แล้ว ไม่ต้องขออนุมัติพล็อตหลักซ้ำ คืนที่แปดมีมนุษย์จริงเฉพาะทีมบริษัท ประยูร และอิง ไม่มี NPC มนุษย์เพิ่มเติม ไม่มี Countdown ไม่มีการบังคับแบ่งทีม โจมตีเพื่อน หรือให้อิงตาย นายโรงมีร่าง Physical ตั้งแต่ต้นคดี

State เปลี่ยนจากเหตุการณ์ที่ Resolve แล้วเท่านั้น การเปิด Q&A การอ่านบท หรือการเปิดหน้า DM ไม่ให้หลักฐาน เปลี่ยน HP ย้ายตำแหน่ง หรือยืนยันการตาย การสังเวยต้องอ้างอิงเหตุที่มนุษย์จริงฆ่ามนุษย์จริงในพื้นที่การแสดงตามเงื่อนไข และเมื่อสำเร็จแล้วไม่ย้อนกลับ

Master Prompt ล่าสุดกำหนดช่องประกาศ Action อิสระ จึงใช้ข้อกำหนดนี้สำหรับ CASE002 แม้ข้อกำหนดการสนทนาก่อนหน้าจะไม่ต้องการช่องส่งข้อความหา DM ช่องนี้เป็นการประกาศสิ่งที่จะทำ ไม่มีคำถามสำเร็จรูป ไม่มีการ Resolve เองจากข้อความ และไม่เปลี่ยน CASE001

## D02 — Defender Response และ `CASE002_DEFENSIVE_ROLL`

**สิ่งที่มีจริง:** `liteDefense` ใช้ PDEF = `10 + BODY`, MDEF = `10 + RES`; Guard เพิ่ม 2 `liteAttack` ใช้ `D20 + bonus >= defense` และ Damage คงที่ ไม่ทอยป้องกัน ไม่มี Partial สำหรับ Attack

Combat Lite v1.1 §6 วาง Reaction ก่อนทอย Hit ส่วนคำขอ CASE002 ต้องการ Attacker Roll ก่อน Identity Reveal แล้วจึง Defender Response จึงเป็นการเปลี่ยนลำดับที่ต้องกำหนดแยก ไม่สามารถอ้างว่า Guard เดิมเปิดใช้ย้อนหลังหลังเห็นผลได้

### D02-A — ใช้ Fixed Defense และ Reaction ก่อนทอยตามฐานเดิม

แนะนำเป็นฐานที่เพิ่มกฎน้อยที่สุด หากผู้ใช้ยอมเปลี่ยนจังหวะเฉลย: ประกาศ Attack และเปิดโอกาสใช้ Reaction ที่ถูก Trigger ก่อนทอย จากนั้น Attacker Roll, Identity Reveal และ Combat Resolution Guard ต้องเตรียมไว้ในเทิร์นตามต้นทุนเดิม ไม่ให้ Guard ฟรีหลังทอย ข้อมูล Reaction ฝ่ายรับต้องไม่ส่งชื่อจริงให้ผู้โจมตีก่อน Reveal

ทางเลือกนี้ **ไม่ตอบความต้องการทอยป้องกันหลังโจมตี** และต้องเขียนข้อจำกัดนี้ตรง ๆ

### D02-B — เลื่อนหน้าต่าง Reaction ไปหลัง Attacker Roll

คง Fixed PDEF/MDEF แต่เปลี่ยนจังหวะเฉพาะ CASE002: Intent → Confirm → Attacker Roll → Identity Reveal เฉพาะผู้มีสิทธิ์ → Reaction ที่เข้าเงื่อนไข → Hit/Damage Resolution ห้ามแสดงผลว่า “โดนแล้ว” ก่อนปิดหน้าต่างนี้

ต้องระบุว่า Reaction ใดใช้ได้จริงกับการโจมตีมนุษย์ด้วยกัน และการเคลื่อนที่/รับแทนมีผลต่อ Attack ที่ทอยแล้วอย่างไร ถ้ารับแทนให้ใช้ Defense ของผู้รับจริง โดยใช้ Attack die เดิม ไม่ทอยโจมตีใหม่ Guard ที่เตรียมไว้ยังมีผลตามฐานที่เลือก แต่ไม่กลายเป็น Reaction ใหม่ ความสามารถที่ Trigger เฉพาะศัตรูหรือผีไม่ขยายมาถึงเพื่อนโดยปริยาย

ทางเลือกนี้เป็น **กฎจังหวะใหม่ที่รออนุมัติ** แม้จะไม่เพิ่ม Defense Roll

### D02-C — `CASE002_DEFENSIVE_ROLL` (อนุมัติแบบกติกาแล้ว; ยังไม่เปิด Runtime)

ผู้ใช้เลือกสูตรต่อไปนี้สำหรับ CASE002 เป็นกฎเพิ่มเฉพาะคดี ยังไม่ใช่สิ่งที่ Runtime ปัจจุบันทำได้:

| หัวข้อ | ข้อเสนอ |
| --- | --- |
| ขอบเขต | CASE002 เท่านั้น; การโจมตีมีผู้รับที่รู้ตัวและมีวิธีรับมือจริง |
| Physical | `defenseTotal = D20 + BODY + preparedGuardBonus` |
| Mental | `defenseTotal = D20 + RES + preparedGuardBonus` |
| Guard | `preparedGuardBonus = 2` เฉพาะ Guard ที่จ่ายและยังไม่หมดสิทธิ์ตามฐานที่อนุมัติ; มิฉะนั้น 0 |
| Hit | frozen `attackTotal >= defenseTotal` ถือว่าโดน; ไม่มี Partial หรือ Critical ใหม่ |
| ความสัมพันธ์กับ PDEF/MDEF | แทนเลขฐาน 10 ด้วย D20 ของการป้องกันครั้งนั้น **ไม่บวก PDEF/MDEF อีกชั้น** และไม่ตรวจ Fixed Defense ก่อนแล้วทอยแก้ |
| Reaction | ใช้สิทธิ์ Reaction ของการรับมือครั้งนี้ ไม่เกิน 1 ครั้ง/ตัวละคร/รอบ; ห้าม Reaction อื่นซ้ำใน Hit เดียว |
| AP / Focus | เสนอ 0 AP / Focus1 / 1 Reaction ต่อรอบ โดยอ้างต้นทุน 0 AP / Focus1 ของ Reaction เดิมเป็นฐานเปรียบเทียบ ไม่ใช่การอ้างว่ามีกฎใหม่นี้อยู่แล้ว; ต้องอนุมัติก่อนใช้ |
| หลัง Hit | Damage คงที่และผลลด Damage ใช้ลำดับของฐานกติกาที่เลือก ไม่เพิ่มเกราะหรือ Damage reduction ใหม่ |
| ข้อห้าม | ไม่ใช้กับผู้หมดสติหรือ Action ที่ไม่มีวิธีป้องกันตามนิยาย; ไม่เปลี่ยน Attack die ย้อนหลัง |

**จังหวะของข้อเสนอ C:** แจ้งโหมดรับมือและจองสิทธิ์ Reaction/Focus1 ก่อน Attacker Roll โดยให้ฝ่ายรับรู้เพียงภัยที่ต้องรับมือและไม่ส่งข้อมูลตัวจริงกลับให้ผู้โจมตี จากนั้น Server ล็อก Attacker Roll, เปิด Identity Reveal ฝ่ายรับ และจึงให้ทอย Defense ตามที่เลือกไว้ จ่าย Focus ครั้งเดียวเมื่อรับมือจริง ไม่ให้เปลี่ยนเป็น Fixed Defense หลังเห็นผล เมื่อเลือก C สำหรับ Hit นี้แล้วไม่ใช้ Reaction อื่นหรือทอย Defense ซ้ำ; Guard ที่เตรียมไว้ใช้ตามสิทธิ์เดิมเท่านั้น

การ Commit ต้องไม่กลายเป็น “ลอง Fixed Defense ก่อน ถ้าโดนค่อยเสี่ยงทอยอีกชั้น” ผู้รับที่เลือกใช้ไม่ได้, ไม่รู้ตัว, ไม่มี Focus/Reaction หรือไม่มีวิธีป้องกันจริง ใช้ Fixed Defense ตามฐานที่อนุมัติ หากต้องการให้เลือกโหมดหลังรู้ผลโจมตี ต้องออกแบบต้นทุนและสมดุลเพิ่มเติม ข้อเสนอ C นี้ให้ **ทอยหลังโจมตี แต่เลือกก่อนรู้ผล** ไม่ใช่สิทธิ์เลือกรับผลที่ดีกว่าระหว่างสองวิธี

**มติ:** ผู้ใช้เลือก C พร้อมสูตร 0 AP/Focus1/1 Reaction และเลือกก่อนรู้ผลโจมตีแล้วทอยหลังเฉลยตัวตน กรณีรับแทนต้องใช้กฎของฐาน v5.5 และไม่ให้ Reaction สองครั้งใน Hit เดียว NPC ไม่มีสิทธิ์ C จนกว่าจะอนุมัติ Focus/Reaction profile ใน D03 ยังไม่มี Defensive Roll เปิดใน Runtime และ A/B เป็นทางเลือกที่ไม่ได้เลือก

## D03 — Lethal, Downed และค่ามนุษย์ที่ไม่ใช่ผู้เล่น

**ช่องว่าง:** Runtime หัก HP ลงถึง 0 แต่ไม่มีตัว Resolve การตายทั่วไปของผู้เล่น/อิง/ประยูร `Character` ไม่มี Danger/Critical/dead ส่วนเหตุถึงตายใน CASE001 เป็นเหตุเฉพาะคดี ห้ามนำมาใช้เป็นสูตรตายของ CASE002

**ข้อเสนอรออนุมัติ:** ใช้ Universal v1.3 §7 เป็นฐานเฉพาะ CASE002:

1. HP0 เป็น Downed เริ่ม Danger0 ไม่ใช่เสียชีวิต
2. ในการต่อสู้ที่ยังมีอันตรายจริง การจบรอบโดยยังไม่ได้ช่วยให้คงที่เพิ่ม Danger1; การถูกโจมตีซ้ำขณะ Downed เพิ่ม Danger1
3. Danger3 เป็น Critical; อันตรายจริงเพิ่ม Danger อีก1ก่อนรักษาจึงเสียชีวิต ต้องมีคำเตือนที่รับรู้ได้ก่อน
4. Stabilized หยุด Danger จากการถูกทิ้งไว้ แต่ไม่ทำให้ทนการโจมตีซ้ำ; HP≥1 ออกจาก Downed/Critical
5. ไม่เพิ่ม Danger จากเวลาเดินเรื่อง การเปิด Q&A หรือการสืบสวนนาน ไม่มี Countdown คดี และไม่ให้ศัตรูทำร้ายคนที่ล้มโดยไม่มี Action/การ Resolve จริง

กติกานี้เป็น PROPOSED ในต้นฉบับ จึงต้องยืนยันก่อนเปิด Runtime รวมถึงต้องเลือกวิธี Stabilize/รักษาให้ตรง D01 เพราะเอกสาร `1 AP + INT DC11` กับ Runtime `stabilize` แบบ `2 AP + knowledge DC8` ไม่ตรงกัน

**ค่าที่ขาด:** HP, BODY/RES หรือ PDEF/MDEF, การเคลื่อนที่ และสิทธิ์ลงมือที่จำเป็นของอิงและประยูร ไม่เสนอเลขแทนโดยเดา ไม่ยก WICHAI มาเป็นอิง ต้องตกลงค่ามนุษย์ทั้งสองพร้อมกติกาการรักษาและการรับแทนก่อนทดสอบ Combat ถึงตาย

**ข้อกำหนดบันทึกสาเหตุ:** Death Event ต้องมีผู้ลงมือจริง ผู้ตาย Action/Attack อ้างอิง สถานที่จริง และสาเหตุที่ Resolve แล้ว การเพิ่ม Danger จากการถูกทิ้งไว้ต้องมี Attribution ที่กำหนดชัดก่อนใช้ยืนยันเครื่องสังเวย ห้ามเหมารวมว่าผู้ที่โจมตีครั้งใดครั้งหนึ่งเป็นผู้ฆ่าในทุกกรณี นายโรงหรือผีฆ่าคนเองไม่นับการสังเวย

| ผีผู้แสดงหน้ากาก | `DROWNED_ECHO` | baseHPFor2 8, PDEF12, MDEF13, ATK3, INIT2, MOVE3 |
| นายโรง ตั้งแต่ต้นจน FINAL | `NANG_TANI_FINAL` | baseHPFor2 14, PDEF14, MDEF16, ATK5, INIT3, MOVE4 |

ข้อเสนอ: ใช้ค่าฐานชุดเดียวของนายโรงตลอดคดี ไม่เพิ่มพลังตอน FINAL ส่วน HP ศัตรูใช้ `ceil(baseHPFor2 × partySize / 2)` ตาม `liteGhostHP` เมื่ออนุมัติแล้ว ต้องกำหนดว่าใช้จำนวนทีมทั้งคดีหรือจำนวนผู้ร่วม Encounter โดยเฉพาะกรณีแยก 1/1 ห้ามอาศัยการ Clamp เป็น 2 ใน CASE001 แล้วเรียกว่ารองรับสมดุลทีมเดี่ยวแล้ว

**ไม่คัดลอกพร้อมตัวเลข:** Anchor กำไลทองเหลือง รากกล้วย ความทรงจำน้ำท่วม Hazard ของแม่แก้ว เงื่อนไขคืนร่าง ตัวประกัน และ Ending ของ CASE001

การเปลี่ยนชื่อท่าไม่ทำให้เป็นท่าใหม่ที่อนุมัติแล้ว ตัวอย่างที่จะเสนอพร้อมค่าเดิมได้คือท่าโจมตีระยะ1 Damage2 vs PDEF ของ Minor สำหรับอาวุธเหล็ก แต่ Range, Damage, Trigger และรายการท่าแต่ละตัวต้องมีแหล่งอ้างอิงและได้รับอนุมัติก่อนเปิดใช้ ไม่มีท่าสังหาร/Auto-hit จากคำบรรยาย

**รอคำตัดสิน:** รับหรือปรับ Numeric Mapping, รายการ Attack ที่ใช้ได้, การ Scale และผล HP0 การที่ร่างสลายต้องไม่ถูกแปลเป็นกำจัดถาวรโดยอัตโนมัติ

## D05 — วิธีจบ FINAL ก่อนและหลังการสังเวย

**ผู้ใช้เลือกทางที่ 2 หลังคำอธิบายแล้ว:** ทั้งสองทางใช้ข้อเท็จจริงเดียวกันว่าเมื่อสังเวยสำเร็จ นายโรงกลับมาถาวรและพิธีปิดโรงเดิมใช้ไม่ได้ ต่างกันว่าคดีนี้จะมีวิธีใหม่สำหรับหยุดภัยถาวรหลังจากนั้นหรือไม่

ตัวอย่างผลผสม: ผู้เล่นช่วยอิงและประยูรออกมาได้ แต่เพื่อนหนึ่งคนเสียชีวิตจากมนุษย์จริงในเขตการแสดงจนสังเวยสำเร็จ ทีมชนะร่างนายโรงใน FINAL ได้เหมือนกันทั้งสองทาง ทางแรกจบด้วยการช่วยคนและเปิดทางหนี โดยนายโรงยังเป็นภัยถาวร จึงเป็น D พร้อม Fallen Agent ส่วนทางที่สอง ถ้าออกแบบและอนุมัติวิธีตัดความคงอยู่ใหม่ไว้ตั้งแต่ช่วงสืบสวน ทีมอาจหยุดภัยถาวรได้หลังลงมือสำเร็จ จึงเป็น C เพราะมีคนตายจริง ไม่ใช่ A และไม่คืนชีวิตหรือย้อนค่า completed

### ทางแรกที่ไม่ได้เลือกเป็นทางจบสูงสุด — ตีเปิดทางหนี

- **ยังไม่สังเวย:** ทีมคุ้มกันมนุษย์ ป้องกันการหลอกให้ฆ่ากัน สู้ให้ร่าง Physical สลายเพื่อเปิดโอกาส และทำพิธีปิดโรงประจำปีที่มีอยู่ให้ครบตามขั้นตอนที่พบตั้งแต่ B3 ต้องเขียนอุปกรณ์ การเข้าถึงตำแหน่ง และ Action ที่ใช้ก่อนล็อก ไม่สร้าง DC/AP ใหม่เอง
- **สังเวยสำเร็จแล้ว:** พิธีเดิมใช้สะกดกลับไม่ได้ การสู้ให้ร่างสลายช่วยเปิดทางอพยพและหยุดการโจมตีขณะนั้นเท่านั้น นายโรงยังคงอยู่ถาวร ภัยไม่ได้จบโดยพิธีเดิม เส้นทางนี้ให้จบ D พร้อมบันทึกผู้รอดชีวิตและการช่วยเหลือจริง ไม่บังคับฆ่าคนเพิ่มหรือเพิ่มพิธีฉุกเฉิน
- ปูความแตกต่างนี้ใน B3 และเอกสารฝั่ง C3 ยืนยันเงื่อนไขเครื่องสังเวยใน E4 หากสำเร็จตั้งแต่ D ให้ทุกบทต่อจากนั้นใช้ข้อความแบบ “กลับมาถาวรแล้ว”

**ข้อจำกัดที่ต้องยอมรับ:** แนวทางนี้ยังไม่มีชัยชนะถาวรหลังสังเวยสำเร็จ ผู้เล่นยังช่วยคนและอพยพต่อได้ FINAL จึงไม่ตัน แต่ไม่เรียกการหนีสำเร็จว่าปิดโรงถาวร

### ทางที่ผู้ใช้เลือก — เพิ่ม Anchor ที่จัดการได้แม้สังเวยแล้ว

หากต้องการให้หยุดภัยถาวรหลังสังเวยได้ อาจออกแบบ Anchor/วิธีตัดความคงอยู่แยกจากพิธีเดิม แต่เป็น **กติกาและข้อเท็จจริงใหม่** ต้องกำหนดที่มา วิธีทำลาย/ตัดสัมพันธ์ ผลต่อร่าง ระยะเข้าถึง ต้นทุนและโอกาสป้องกัน รวมถึงปูหลักฐานตั้งแต่ B3/C3/E4 ก่อน FINAL ไม่มี Anchor นี้ทำงานจากการอ่านเอกสารฉบับนี้

**มติ:** ผู้ใช้เลือกให้ออกแบบ Anchor เพิ่ม ทางหยุดภัยใหม่ใช้ได้ทั้งก่อนและหลังสังเวย ไม่ย้อนล้างการตายหรือค่า completed รายละเอียดปูหลักฐาน/ผล State อยู่ใน [FINAL Anchor Design](CASE002_FINAL_Anchor_Design.md); กลไกตัวเลขยังเป็น Draft

## D06 — Priority ของ Ending และกรณีผลผสม

Draft Resolver ใช้จากบนลงล่าง อ่าน State จริงหลังจบเหตุ ไม่ตัดสินจากเลขฉากหรือจำนวน Check ที่สำเร็จ:

| ลำดับ | Ending | เงื่อนไข Draft |
| --- | --- | --- |
| 1 | D | นายโรงยังเป็นภัยที่ควบคุมไม่ได้ ทีมพ่ายแพ้ หรือถอนตัวโดยยังควบคุมภัยไม่ได้; รวมสังเวยสำเร็จแล้วร่างสลายแต่จุดยึดยังไม่ถูกตัดตาม D05 |
| 2 | C | หยุดภัยสำเร็จจริง และมีการตายจากเหตุที่ Resolve แล้ว ไม่ว่าผู้ลงมือเป็นผู้เล่น นายโรง หรือเหตุอื่น |
| 3 | A | หยุดภัยสำเร็จ ไม่มีสังเวย ไม่มีผู้เสียชีวิต อิงและประยูรปลอดภัย |
| 4 | B | ไม่มีสังเวย ไม่มีผู้เสียชีวิต ช่วยผู้รอดชีวิตออกมาได้ และควบคุมภัยไว้ได้ตามนิยามที่อนุมัติ แม้ยังยุติภัยไม่สมบูรณ์ |
| 5 | D | ผลที่เหลือซึ่งยังพิสูจน์เงื่อนไข A/B/C ไม่ครบ; บรรยายตามสิ่งที่ทราบ ไม่แต่งการตายหรือชัยชนะเพิ่ม |

**ยังต้องล็อก:** ความหมายของ `stopped`, `contained`, “ปลอดภัย” และการยืนยันออกจากพื้นที่ ห้ามให้ B กลบกรณีถอนตัวทิ้งภัยที่ควบคุมไม่ได้ D05 เลือก Anchor ใหม่แล้ว จึงรองรับ C หลังสังเวยเมื่อจุดยึดถูกตัดและร่างที่เป็นภัยถูกหยุดจริง โดยไม่ย้อนล้าง completed

`Fallen Agent` เป็น Modifier เมื่อมี Player Death จริง ใช้ประกอบ Ending ที่ Resolve ได้ ไม่เปลี่ยนเหตุการตายและไม่ทำให้ผู้อื่นตายตาม มีรายงานแยกผู้เสียชีวิต ผู้ลงมือ สถานะสังเวย การช่วยเหลือ และผลปิดโรงเสมอ

**รอคำตัดสิน:** อนุมัติ Priority และนิยามผลผสมก่อนเขียน Resolver ที่เปิดใช้

## D07 — DC ของ Dice Cards และผลได้เปรียบ

Core ให้ระดับ DC11/14/17/20/22 แต่ไม่ได้ให้สิทธิ์ถือว่า Check ใหม่แต่ละใบมีเลขอนุมัติแล้ว

ข้อเสนอสำหรับ Pack ฉบับนี้: เริ่มพิจารณา Standard14 สำหรับการตรวจที่มีความเสี่ยงปกติ และ Hard17 สำหรับการตรวจในข้อจำกัดจริง ระบุ `proposed_dc` กับ `approval_pending`; ค่าที่เปิดใช้ต้องยังว่างจนอนุมัติ ไม่เพิ่มDCเพียงเพราะต้องการซ่อนเบาะแส

- ใช้ PER/INT/SPI/RES ตามวิธีที่ผู้เล่นประกาศและ Trigger ที่ฉากรองรับ ไม่เปลี่ยน Core Stat
- การอ่านข้อมูลที่เปิดอยู่ ตรวจเสื้อ/อุปกรณ์ที่เห็นชัด หรือใช้รหัสสื่อสารที่ตกลงกันได้ ไม่บังคับทอย
- Full ให้รายละเอียดที่มีอยู่จริง Partial มีผลเฉพาะ Action ที่ออกแบบรองรับ Failure มีทางสืบต่อ ไม่มีการตาย/หัก HP จากการสอบสวนพลาดโดยไม่มีเหตุและกฎ
- ได้เปรียบจากหลักฐานอาจเป็นข้อมูลช่วยตัดสินใจโดยไม่เพิ่มเลข หากต้องให้โบนัส ต้องอ้างกฎที่อนุมัติและกำหนดการใช้/การไม่ซ้อนก่อน
- Attack Roll, Defensive Roll ที่เสนอ และผล Damage ไม่รวมในจำนวน Dice Cards สืบสวน

## เงื่อนไขก่อน Integration ที่เปิดเล่นจริง

เตรียม StoryScript, Evidence Chain, DM Runbook, Contract ฉบับ Draft และ Compatibility Plan ต่อได้ภายในพล็อตที่อนุมัติแล้ว แต่ยังไม่แสดง CASE002 ว่า “พร้อมเล่น” ก่อนแก้ประเด็น D01–D07 ที่เกี่ยวข้องและผ่าน QA จริง ไม่มีการถือว่าผู้ใช้เงียบแล้วเท่ากับอนุมัติ

คำตอบแต่ละข้อควรระบุรหัสและทางเลือก เช่น `D01 A; D02 A; D05 แนวทางแนะนำ` ส่วนค่ามนุษย์ รายการท่าศัตรู และจังหวะ/ต้นทุนที่ยังไม่มีตัวเลขต้องได้ข้อสรุปเพิ่ม ไม่ปิดช่องว่างด้วยค่าเดา ระหว่างนี้ CASE001 และเซฟเดิมต้องคงพฤติกรรมเดิม

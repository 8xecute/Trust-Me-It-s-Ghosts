# PROMPT สำหรับ CODEX — อัปเกรด CASE 001 จาก v4.3 เป็น v5.1

คุณคือ Senior Narrative Systems Engineer + Game QA สำหรับเกมออนไลน์ Cooperative Horror TRPG **บริษัท เรื่องผีไว้ใจผม จำกัด** (DM 1 คน, ผู้เล่นเป้าหมาย 2–6 คน) ที่มีโค้ดเกมใช้งานอยู่แล้ว

## เป้าหมายงาน

**อัปเดตเนื้อหาและระบบที่อิง CASE 001 — เสียงร้องจากสวนกล้วย จาก Story Script v4.3 ให้ตรงกับ Story Script v5.1** โดยรักษาโครงเกมเดิมและไม่สร้างเกมขึ้นใหม่ การอัปเกรดนี้ครอบคลุมบทบรรยาย/บทพูด/เงื่อนไขปลดบท/หลักฐาน/ทางสำรอง/การจัดการ State/การตาย/Ending/การแสดงผลของ DM และการทดสอบ ไม่ใช่แค่เปลี่ยนข้อความในไฟล์ Markdown

ก่อนแก้ไขให้ตรวจโครงสร้าง repository และระบบปัจจุบันว่าบทถูกเก็บใน Markdown, JSON, database, script, state machine, UI หรือหลายแหล่งพร้อมกัน แล้วแก้ให้แหล่งข้อมูลที่เกมใช้จริงตรงกันทั้งหมด อย่าแก้เฉพาะไฟล์เอกสารโดยไม่เชื่อมกับ runtime และอย่าแก้ระบบส่วนอื่นที่ไม่เกี่ยวข้อง

## A. สรุปวิวัฒนาการจาก v4.3 → v5.1 เพื่อเข้าใจว่าทำไมต้องแก้

- **v4.3 — Guided Linear Investigation:** โครง `A → B → C → D → E → FINAL → ENDING`; ปิดบทแล้วไม่ย้อนกลับ; สืบภายในบทได้อิสระ; 31 ฉาก (`A1–F6`, `H1`), 16 Dice Checks, Ending A–D, fail-forward และเบาะแสหลักไม่ถูกล็อกด้วยการทอยครั้งเดียว
- **v4.4 — Editorial Continuity:** เกลี่ยเหตุ-ผล ความรู้ของ NPC บทเชื่อมระหว่างฉาก คำให้การ/เอกสาร/ความทรงจำ และลดคำบรรยายซ้ำ; สู้ เจรจา หรือถอยต้องมีผลจริง
- **v4.5 — Evidence-Driven:** ผู้เล่นต้อง *เห็นสิ่งตั้งต้นก่อนมีเหตุให้ถาม* เช่น B1 มีแผนที่หมุดคนหายซ้อนวงงานที่ดิน จึงถามวิชัยใน B2 ได้อย่างเป็นธรรมชาติ; C2 ชี้ทางยายบุญมี; D1 ปูรอยพื้นก่อน D5; บอกแหล่งหลักฐาน 2 ชุดสำหรับ Check C5 เป็น Editorial Props ที่ยังต้องอนุมัติ
- **v4.6 — Motivation & Logic:** วิชัยลักพาตัวเพื่อปิดปากและซื้อเวลาจนได้เงินแล้วหนี (ไม่มีแผนปล่อยตัวที่สมเหตุสมผล); ป้ายชื่อคนหายใช้ป้ายความผิดให้ผี; วิชัยหลอกแม่แก้วว่าการปรากฏตัวจะกระตุ้นให้คนขุดเหตุปี 2534 แล้วจึงบังคับด้วยกำไล; ประเสริฐเรียกทีมเพราะคนหายและหมู่บ้านกำลังล่ม; ต้นมีเหตุอยู่บ้านผู้ใหญ่และไม่ได้เห็นการลักพาตัวโดยตรง
- **v4.7 — Bloodstained/Lethal Playtest:** เพิ่มรอยรุนแรงที่เห็นได้จริง (มือวิชัย ผีเงาจมน้ำ คนหาย บันทึกอำมหิต) และ Death Triggers แบบมีเงื่อนไข: E5 ตัวประกันถูกใช้เป็นโล่เมื่ออยู่ในระยะจริง, F6 Ritual Toll เวลา 03:00, F5 แม่แก้วพยายามฆ่าวิชัยหลังเป็นอิสระ; ห้ามฆ่าอัตโนมัติจากการทอยพลาดอย่างเดียว/ไม่เห็นเหตุ/ไม่มีโอกาสรับมือ; การตายปิด Ending A
- **v4.8 — Dialogue Continuity:** เพิ่มพูดขาดห้วงเพราะช็อก; ต้นปะติดปะต่อผู้ต้องสงสัยจากเสื้อ/รอยมือ ไม่อ้างเห็นหน้าในสวน; ยายบุญมีไม่ใช่หมออาคม; แม่แก้วพูดชื่อผู้บงการในบริบทกล่าวหาไม่ได้เพราะด้ายรัด; วิชัยมีจังหวะตะคอก/ชักมีดก่อนคุกคาม
- **v4.9 — Survival & Trauma:** นิดขอให้พาหนีด้วยความตื่นกลัว; ดลห่วงชีวิตและโกรธก่อนกล่าวถึงสมุด; วิชัยร้องขอชีวิตเมื่อแม่แก้วลงมือ; ประเสริฐหลบเลี่ยงก่อนจำนนต่อหลักฐาน; ผู้เห็นคนตายมีปฏิกิริยาต่อเนื่อง ไม่พูดเหมือนไม่มีอะไรเกิดขึ้น
- **v5.0 — DM Reader Edition:** จัดฉากเป็นเป้าหมาย/ผู้ที่อยู่จริง/DM อ่าน/NPC พูด/ตอบคำถาม/แหล่งเบาะแส/ทางสำรอง/บทเชื่อม/DM ลับ มีสารบัญและตัวกรองข้อมูล; เป็นการจัดรูปแบบ ไม่ใช่เปลี่ยนหลักเรื่อง
- **v5.1 — State Consistency Audit (ล่าสุด):** ระบุ initial states และ transitions ที่ขาด เช่น `KAEW_D_RESULT=not_met`, `GHOST_ENCOUNTER`, `HOSTAGE_FATE`, `RITUAL_TETHER_INTACT`, ประเมิน `RITUAL_0300_FULL_POWER` ก่อนเปลี่ยนสถานะพิธี; คง 31 ฉาก/16 Dice Checks/Ending เดิม และเปิดเผยข้อที่ยังไม่มีวิธีตัดสิน

## B. ข้อเท็จจริงของคดีที่ห้ามเปลี่ยน

1. วิชัยเป็นมนุษย์ที่ลักพาตัว **ดล นิด เพิ่ม**; ผีเงาจมน้ำหรือแม่แก้วไม่ได้เป็นคนลักพาตัว
2. แรงจูงใจวิชัย: หนี้, เงินจากธุรกรรมที่ดิน, การใช้ข่าวผีข่มขู่ให้คนยอมขาย, ความสิ้นหวัง/ตั้งใจหนีเมื่อแผนพัง
3. ปี 2534 มีการ **เปิด** ประตูผันน้ำระหว่างยังอพยพไม่ครบ; ประเสริฐร่วมรับผิด แต่ห้ามสรุปว่าเป็นผู้สั่งสูงสุดคนเดียวโดยไร้หลักฐาน; ยายบุญมี **ไม่ได้เห็นการเปิดประตูน้ำกับตา**
4. แม่แก้วช่วย **วิชัยเพียงคนเดียว** ตอนเขาเป็นเด็กและเสียชีวิตในน้ำท่วม; เธอเคยร่วมมือเพราะถูกหลอกว่าจะเปิดโปงความจริง ก่อนถูกวิชัยบังคับด้วยพิธี
5. แม่แก้วรู้ว่าใครเกี่ยวข้อง แต่ข้อห้ามของอาคมทำให้กล่าวหาโดยตรงไม่ได้ ไม่ใช่ความจำเสื่อม
6. ด้ายดำ/ป้ายชื่อ/กำไลเป็น **พิธีผูกวิญญาณชุดเดียว** โดยกำไลคือแกน; ชนะการปะทะที่ D4 ไม่ได้ฆ่าแม่แก้วหรือหยุดพิธี
7. ชื่อบนศาลเป็นการจัดฉากให้ชาวบ้านโยนความผิดให้ผี; ต้นเห็นการเข็นห่อคลุมหนัก ไม่เห็นการลักพาตัวหรือของข้างในชัด
8. เวลา 03:00 **ไม่ใช่ Game Over**; ใน Lethal Variant เท่านั้นมี Ritual Toll ตามเงื่อนไขจริงและทีมเล่นต่อได้
9. อย่าเพิ่มตัวร้าย/ผู้บงการ/ศัตรู/ปมใหม่เพื่ออุดช่องโหว่; การพาดพิงคนกลางหรือ Easter egg ไม่ใช่สิทธิให้สร้างตัวละครใหม่ใน CASE 001
10. ทุก Ending สะท้อนสิ่งที่ทีมทำสำเร็จจริง ไม่บังคับจบดี

## C. อัปเดตฉากและข้อมูลที่เกมใช้จริง

ต้องมีฉากครบ (รักษา ID เดิม):

- A: `A1 A2 A3`
- B: `B1 B2 B3 B4 B5`
- C: `C1 C2 C3 C4 C5`
- D: `D1 D2 D3 D4 D5`
- E: `E1 E2 E3 E4 E5 H1 E6`
- FINAL: `F1 F2 F3 F4 F5 F6`
- Ending: `A B C D` ตาม Resolver ใน v5.1

ทุกฉากในระบบควรแยกชนิดข้อมูล: (1) จุดประสงค์/Trigger (2) NPC ที่อยู่จริง + อารมณ์ + สิ่งที่ต้องการ (3) `dmReadAloud` (4) `npcLines` ตาม Trigger (5) `responses` ตามคำถาม/หลักฐาน (6) `clues` แยกเห็นทันที/ถามตรวจ/ข้อสรุปที่ยังห้ามทำ (7) `fallback` เมื่อข้าม/ทอยพลาด (8) `nextSceneHandoff` (9) `dmSecret` และการเปลี่ยน State. ปรับให้เข้ากับ schema ของ repo ที่มีอยู่ก่อน อย่าเปลี่ยน schema โดยไม่ตรวจตัวเรียกใช้

**เนื้อหาสำคัญตาม Act**

- **A1–A3:** ประเสริฐมีเหตุผลว่าทำไมเรียกบริษัททั้งที่มีความลับ; ตำรวจตรวจตามหน้าที่แต่เหตุเหนือธรรมชาติยังไม่คลี่คลาย; ทีมทราบชื่อสามคนหายและเหตุให้ไปบ้านผู้ใหญ่. ไม่ให้ประเสริฐพูดเหมือนสารภาพปี 2534 ตั้งแต่ต้น
- **B1–B5:** แผนที่คนหาย + งานที่ดินปรากฏก่อน B2; วิชัยใช้ข้อมูลจริงปกปิดความผิด; ต้นไม่แน่ใจในสวนและค่อยมองรอยมือ/เสื้อที่บ้านผู้ใหญ่; คำให้การของต้นเป็นเบาะแส ไม่ใช่หลักฐานพิสูจน์ลักพาตัว; B4 ปูเรื่องน้ำท่วมโดยไม่เฉลยผู้สั่ง; ไปบ้านดลเพราะสมุดที่นั่น
- **C1–C5:** สมุดดล E02 เชื่อมราคาที่ดิน/หนี้/ศาล; ผีเงาจมน้ำมีภาพรุนแรงและเป็น Encounter ที่สู้ สงบ หรือถอยได้ ไม่บังคับเปิดเผยคนร้าย; ยายบุญมีรู้ตามสิ่งที่เคยเห็น/ได้ยิน ไม่รู้กลไกกำไล; ให้เหตุผลไปสวนกล้วย
- **D1–D5:** ด้ายดำ ป้ายชื่อคนหาย แม่แก้วถูกคุม รอยล้อเชื่อมเรือนร้าง; แม่แก้วพยายามพูดชื่อผู้บงการแล้วถูกอาคมรัด; คำเตือนเรื่องตัดด้ายเป็นข้อมูลจากความเจ็บปวด ไม่ยืนยันว่าตัดทุกเส้น = หยุดพิธี; D4 optional และ `won` ≠ หยุดพิธี
- **E1–E6/H1:** ตัวประกันถูกขังและบาดเจ็บจริง; นิดหวาดกลัว ดลโกรธ/ห่วงเพื่อน เพิ่มพูดสั้นเพราะช็อก; E3 แต่ละคนมีขอบเขตพยานของตัวเอง; E4 กำไล แฟ้ม/บันทึก และรอยความคิดฆ่าปิดปากของวิชัย; E5 จะเกิด **เฉพาะวิชัยเดินทางมาปรากฏตัวจริง** และมีตำแหน่ง/โอกาสคุกคามได้; H1 คือการสังเคราะห์เอกสาร ไม่ใช่พื้นที่วาร์ป NPC; E6 สรุปสิ่งที่ต้องทำต่อ โดยแยกช่วยคน/พิสูจน์คดี/หยุดพิธี
- **F1–F6:** แก้ภัยจากกำไลตามสถานะจริง สู้/เจรจา/ถอย/ทดลองได้ในขอบเขตกติกา; F2 ตอบตามผลพบแม่แก้วที่ D; F5 แม่แก้วมีอิสระแล้วอาจลงมือกับวิชัยเฉพาะเงื่อนไขจริง วิชัยต้องร้องขอชีวิตและทีมมีโอกาสเข้าขัดขวาง; F6 ตรวจเวลา 03:00 เป็นเหตุการณ์ตามเวลา ไม่ใช่การบังคับให้ถึง F6 ก่อนจึงเกิด

**สิ่งที่เห็นง่ายไม่ต้องทอย:** ชื่อคนหายบนเอกสาร, สิ่งของที่วางอยู่ต่อหน้า, ข้อความที่อ่านได้ชัด, ทางไปสถานที่ซึ่งมีผู้ให้ข้อมูลที่น่าเชื่อถือ. Dice Check ใช้เปลี่ยนระดับข้อมูล ความเร็ว ความเสี่ยง หรือท่าที แต่ห้ามล็อกเบาะแสหลักจนเดินต่อไม่ได้

จำนวนผู้เล่นเป้าหมาย 2–6 มีผลต่อการรองรับบทและ UX แต่ห้ามปรับ HP, DC, AP/Focus, สเกลศัตรู, การฟื้น, ความตาย HP0 โดยเดาเองหากไม่มีกติกาอนุมัติ

## E. Lethal Variant (จาก v4.7) — เงื่อนไขต้องครบก่อนเกิดเหตุ

1. **E5 Crossfire Death:** ถ้าวิชัยอยู่จริง มีตัวประกันอยู่ในระยะ คว้าตัวประกันได้ตามกติกา และทีมยังโจมตีเสี่ยง/คุ้มกันไม่สำเร็จ จึงเกิดการเสียชีวิตได้; SOC <= 10 เป็นความล้มเหลวรุนแรงภายใน Check แต่ **ไม่ใช่คำสั่งฆ่าโดยอัตโนมัติ**; ถ้าตัวประกันถูกพาออกจริงแล้ว ห้ามเสกคนกลับเป็นโล่
2. **F6 Ritual Toll:** เมื่อเกมข้าม 03:00 ตรวจเพียงครั้งเดียวด้วยสถานะพิธี ณ ก่อนเวลา; ถ้า `RITUAL_0300_FULL_POWER=true`, `RITUAL_TETHER_INTACT['เพิ่ม']=true` และ `HOSTAGE_FATE['เพิ่ม']='alive'` จึงเกิดการเสียชีวิตแบบ `ritual_toll`; ไม่จบเกมทันทีและไม่สังหารคนอื่นอัตโนมัติ; ดึงตัวประกันออกจากเรือนอย่างเดียวไม่เท่ากับปลดด้าย
3. **F5 Kaew Execution Attempt:** เมื่อพิธีหยุดและแม่แก้วเป็นอิสระ วิชัยอยู่ในฉาก/เข้าถึงได้ และเงื่อนไขความโกรธหรือการเจรจาล้มเหลวอย่างมีนัยสำคัญเกิดขึ้นจริง จึงพยายามฆ่า; ให้ telegraph/จังหวะป้องกันตามกติกา; ไม่วาร์ปวิชัย; ผู้เล่นต้องมีการตัดสินใจทางศีลธรรมว่าจะช่วยผู้ร้ายหรือไม่
4. **Player death:** เฉพาะตาม Lethal Playtest Variant และกติกา HP0 ที่อนุมัติ; ต้องมี event จริง, ปรับ State และมีบทตอบของ NPC ที่เห็น/รับข่าว ไม่ประกาศคนตายจากคำบรรยายลอย ๆ

Lethal Variant ต้องแยก config/flag ชัดจากกติกาเดิม และแสดงว่ากฎความตายเวลา 03:00 เปลี่ยนจาก baseline v4.3; ห้ามเรียกว่ากฎเดิมตั้งแต่ต้น

## F. State Contract / Reachability Audit

ให้ใช้ State Contract จาก v5.1 โดยตรวจ Initial → Writer/Trigger → Reader/Branch สำหรับ **ทุก** State และห้าม condition ที่ไม่มีทางเกิด:

- `KAEW_D_RESULT` เริ่ม `not_met`; ถ้า D3 เกิดการสนทนาจริง → `talked`; D4 เกิดและตัดสินผลจริง → `won|fled|lost` (หรือผลที่ฉบับรองรับ). F2 อ่านตามค่าที่มี; อย่าให้ `not_met` เท่ากับแค่ข้าม D4
- `GHOST_ENCOUNTER` เริ่ม `not_started`; C4 ต้องเขียน `won|pacified|escaped|lost` ตามเหตุจริง
- `KAEW_TRUST=neutral`, `GHOST_CLUE=none`, `RITUAL_STATUS=active`, `RITUAL_PLAN=unknown`, `WICHAI_STATUS=free`, `WICHAI_COOPERATING=false`, `BRIBE_ACCEPTED=false` และ initial อื่น ๆ ให้ยึด v5.1
- `HOSTAGE_FATE` เริ่ม `alive` ทั้งสาม, `HOSTAGES_DEAD=0`; คนตายต้องไม่ถูกนับว่า safe และห้ามตายซ้ำ
- `RITUAL_TETHER_INTACT[ดล/นิด/เพิ่ม]` เริ่ม `true`; false เมื่อเกิด Action ปลดสายของคนนั้นจริง ไม่ใช่แค่ย้ายสถานที่
- เวลาเริ่ม 23:00 ถ้าใช้ minutes elapsed ให้ `TIME_MINUTES=0`; 03:00 วันถัดไปเป็นนาทีที่ 240, ตรวจ crossing หนเดียว; `RITUAL_0300_PRESTATE` ต้องบันทึก **ก่อน** เปลี่ยนพิธีเป็น `entrenched` และ `RITUAL_0300_FULL_POWER` ไม่ขึ้นกับว่าเพิ่มตายหรือไม่
- `LAND_EVIDENCE_COLLECTED`, `FLOOD_EVIDENCE_COLLECTED` ไม่แปลว่าเพียงพอทางคดี หรือได้ส่งมอบ/เปิดเผยต่อสาธารณะแล้ว
- `CHECK_RESULTS` เริ่ม `{}`; มี entry เฉพาะ Check ที่เกิดจริง
- `KAEW_FINAL=controlled` หลัง stopped ยังเป็น dead branch; `sealed/departed` และ recovery ของ `KAEW_TEMP_DISPERSED` ยังขาดกฎล็อก **ให้รายงานว่า unresolved อย่าเติมเงื่อนไข/โบนัส/penalty เอง**

### State Improvements ที่คุยต่อหลัง v5.1 — **ข้อเสนอ v5.2 ยังไม่อนุมัติ**

ทำ impact analysis และเสนอ patch ต่างหาก โดยไม่ถือว่าเป็น Canon ใหม่อัตโนมัติ:

- เปลี่ยนการเก็บตัวประกันให้มี record รายคน (`found`, `evacuated`, `fate`, `tetherIntact`, `deathCause`) แล้ว derive `HOSTAGES_FOUND/SAFE/DEAD` เพื่อป้องกันตัวเลขไม่ตรงกัน; ถ้าทำต้อง migration save data และ mapping ชื่อ State เก่า
- กำหนด invariant ว่า `RITUAL_STATUS=stopped` จะมีผลอย่างไรต่อ tether ทั้งสามตามความหมายของระบบพิธีชุดเดียว (อย่าปลดสถานะผิดลำดับหากมี ritual phase)
- แยก `evidence collected` / `evidence legally sufficient` / `evidence actually disclosed` เพื่อให้ Ending A ไม่ผ่านจากการหยิบเอกสารเฉย ๆ
- พิจารณาสถานะ `met_but_no_conversation` เฉพาะกรณีพบแม่แก้วแต่ไม่คุย โดยต้องรักษาความเข้ากันได้กับ `KAEW_D_RESULT` เดิม; ถ้าไม่จำเป็นอย่าเพิ่ม enum
- เลือกทางจัดการ `KAEW_FINAL=controlled` ที่ไม่มี producer, วิธี `sealed/departed`, recovery หลัง D4 และ Critical Fail/HP0 ก่อนปล่อย production

ให้สรุปเป็น **Must Fix / Proposed Improvement / Needs Rules Decision** พร้อมผลกระทบต่อ State และไฟล์ที่ต้องแก้

## G. Ending Resolver ต้องใช้ตามลำดับใน v5.1

1. ถ้า `PLAYER_DEATHS>=1` → D: Fallen Agent (รายงานสถานะพิธีจริง อย่าบอกว่าหมู่บ้านยังต้องสาปถ้าหยุดพิธีแล้ว)
2. พิธียังไม่หยุดและทีมยุติภารกิจโดยควบคุมภัยไม่ได้ → D: หมู่บ้านต้องสาป
3. พิธีหยุดและตัวประกันตาย ≥1 → C: Bloodstained Rescue
4. พิธีหยุด ตัวประกันรอดครบ ผู้เล่นไม่ตาย วิชัยถูกแม่แก้วฆ่าจริง → B: Vigilante Ghost
5. พิธีหยุด แต่ช่วยคนไม่ครบ/วิชัยหนี/คดีมนุษย์ยังไม่มีหลักฐานพอ → C
6. พิธีหยุด คนหายรอดครบ แต่แม่แก้วยังไม่สงบและเป็นภัย → B ตามสถานะจริงที่มีทางเกิด
7. พิธีหยุด คนหายปลอดภัยครบ มีหลักฐานเอาผิดวิชัย, **เปิดเผยอดีตปี 2534 แล้วจริง**, แม่แก้วยุติภัยสมัครใจ และไม่มีใครตาย → A
8. กรณีผสมอื่น ๆ ให้เก็บ modifier และรายงานความสำเร็จ/ความสูญเสียตามความจริง ห้ามฝืน A

ถ้าผล Ending เปลี่ยน ให้บทสรุปใช้จำนวนผู้รอดจริง, สาเหตุการตายจริง, ตัวละครที่อยู่จริง, หลักฐานที่เผยแพร่จริง และคำพูดที่ตรงกับภาวะ trauma

## H. ตัวตรวจระบบและชุดทดสอบที่ต้องเพิ่ม

ทำ automated tests หรือ simulation ตามสถาปัตยกรรม repo ให้ครอบคลุมอย่างน้อย:

- รวม scene IDs ครบ **31**, Ending IDs A–D, Dice IDs ครบ **16** และ DC/Ability เท่าต้นฉบับ
- เส้นหลัก A→B→C→D→E→FINAL→ENDING ไม่ย้อนบทที่ปิดแล้ว แต่ optional scenes ข้ามได้โดยไม่ softlock
- B1 ปูวงสีน้ำเงินก่อน B2 ถามงานที่ดิน; ข้าม B3 ก็ยังพบสมุด C2 และสืบได้
- D3 คุยแต่ไม่สู้ → F2 ใช้ `talked`; ข้าม D3 จริง → F2 ใช้ `not_met`; D4 won ≠ stopped
- C4 หนี/สงบ/ชนะ/แพ้ โดยไม่บังคับพบวิชัยจากภาพผี
- E5 วิชัยไม่ได้อยู่เรือนจริง → ห้ามแสดงบทเขา/ห้าม Crossfire; ตัวประกันปลอดภัยแล้ว → ห้ามถูกคว้ามาเป็นโล่
- E4 อ่านกำไลผ่าน Dice success ≠ หยุดพิธีทันที
- F6 03:00 เมื่อ ritual active + tether เพิ่ม intact + เพิ่ม alive → Toll ครั้งเดียว; ritual weakened/stopped หรือสายเพิ่มปลดแล้ว → ไม่มี Toll; 03:00 ไม่ Game Over
- ทีมไปถึง 03:00 ขณะที่ยังอยู่ E → ตรวจเวลาได้โดยไม่ต้องรอ F6
- F5 วิชัยไม่อยู่ → ไม่มีการฆ่าวาร์ป; วิชัยอยู่และแม่แก้วพยายามฆ่า → มีจังหวะ reaction
- ตัวประกันตายแล้วค่า safe ต้องลดและ deathCause ถูกบันทึกเพียงครั้งเดียว
- Ending A ต้องไม่เกิดเมื่อมีผู้ตาย, เอกสารยังไม่ถูกเปิดเผย, หรือวิชัยถูกแม่แก้วฆ่า
- Ending B/C/D แบบเลือดมีบทตอบจาก NPC ที่รู้เหตุจริงเท่านั้น
- Reload / save / resume ต้องไม่ trigger ความตาย 03:00 ซ้ำ ไม่ย้อน state และไม่เผย DM secret ในหน้าผู้เล่น
- State ทุกค่าที่มี conditional dialogue ต้องมี producer ที่ reachable จริง; รายงาน branches ที่ยังเป็น dead/undefined โดยเฉพาะ controlled/sealed/departed
